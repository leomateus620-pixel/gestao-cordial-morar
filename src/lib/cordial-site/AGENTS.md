# Public sites (src/lib/cordial-site)
- Site SEO: layouts (/site, /site-morar) emit only brand icons, theme, verification and RealEstateAgent JSON-LD via siteLayoutHead; canonical/og:url/og:image/twitter:image come only from each leaf siteHead, with the brand og-default.jpg as fallback — why: TanStack concatenates links, which produced two canonicals, and hosting injected the Gestão share image.
- src/server.ts copies string Worker env bindings into process.env before guardSiteRequest; legacy /imovel/{digits} resolves via service-only <brand>_site_resolve_legacy (manual *_site_redirects first) to a single 301, 410 when withdrawn, normal 404 when unknown — why: process.env was empty there in production, so /sitemap.xml and redirects never ran.
- Public sites show no consent banner (owner decision): visit/audience measurement and GA/GTM analytics_storage run for every visitor and are explained on the privacy page; Meta Pixel is never loaded and ad_* signals stay denied — why: owner wants measurement without prompts, ads still need a choice.
- Property URLs are `/imovel/<descriptive-slug>-<public uuid>` built only by property-slug.ts (site links, sitemap, legacy 301); detail routes parse the trailing uuid and 301 any other form to propertySlug — why: unique per brand without a DB column, old uuid links keep working.
- Banners, quick searches, search types, default order, featured mix and per-property SEO overrides live in the brand settings content (settingsSchema), with pure rules in banners.ts / search-settings.ts / home-selection.ts — why: no new tables; brand separation follows the settings row.
- Manual redirects are written only by redirects.functions.ts (admin check, preview recomputed server-side) as `/imovel/<id>/`; robots.txt points to <api>/sitemap.xml because hosting intercepts root /sitemap.xml on custom domains — why: hand-added journal entries are forbidden and production shares the database.
- Google tags on public sites: the Cordial GTM snippet is decided server-side (gtm-install.ts, by request host) and rendered once in RootShell; client code never adds a second Google tag while it exists — why: one tag per page and no leak to Morar/Gestão/previews.
