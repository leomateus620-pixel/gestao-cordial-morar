# Vistoria

- Vistoria photos: "Tirar foto" opens the in-app camera (getUserMedia, tracks stopped on close/hidden/unmount) with native camera only as secondary/fallback; every photo goes through image-prepare (reduced decode + thumbnail, original only JPEG/PNG ≤15 MB) one at a time; native/gallery opens arm a capture-resume marker shown only after a real reload; local previews use thumbnails via incremental object URLs; upload retries use per-entry backoff (nextAttemptAt) without blocking others — why: Android kills the tab while the native camera is open and full-size decodes/previews exhaust memory.
- Vistoria voice transcription runs in useTranscriptionRunner (separate from the upload queue) through transcribeNote; claim/renew/finish RPCs own lease, attempts and errors (402/429/5xx/network retry later without spending attempts, 400/403 terminal); large WAV is read by byte ranges and split frame-aligned; voice deletion goes through deleteVoiceNote and re-recording deletes the old note only after the new one is confirmed — why: no duplicate work, no stuck notes, no lost audio.
- Migration numbering: 0115 is the voice-transcription migration (already applied; never renumber); the ".." storage-path rule for properties 1444/3441 takes the next free journal number (0116–0122 are already used) — why: renaming an applied migration would diverge the Drizzle journal from the database.
