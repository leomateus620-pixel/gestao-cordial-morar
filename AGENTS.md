- Rotinas automáticas (gatilhos/crons → /api/public/hooks/*) autenticam com `public.internal_worker_headers()` (credencial no cofre); nunca chave pública — why: evita 401 silencioso e segredo em texto.

- Arquivamento de imóvel: pedido, conclusão e reativação passam pelas RPCs property_retire_request / property_archive_finalize / property_unarchive (só service_role); um destino só conta como retirado quando confirmado na intenção de arquivamento (`archive_intent_revision`) — why: enabled=false não comprova retirada e evita concluir cedo demais.

- NFS-e: só o servidor grava em rental_nfse_emissions e registra cada transição em rental_nfse_emission_events (linha `processando` antes do envio, identificador determinístico, nunca reenvio automático de nota real; `incerto` só por incerteza de transporte/corpo; liberação manual só por `nao_emitida` com motivo) — why: evita nota duplicada, sem registro ou competência travada.
- Conclusão do cadastro de imóvel passa só por `finalizePropertyRegistration` (salvar, códigos, agenciamento, publicação e marca de concluído), e publicar imóvel do Gestão sem agenciamento cria o agenciamento automático pela chave `property:<id>:initial-agency-listing` sem sobrescrever; o responsável do agenciamento é o corretor escolhido/do imóvel, senão quem cadastrou (qualquer perfil); só clicar em concluir/publicar não torna admin/secretária responsável, e gatilhos de fila nunca podem falhar por conflito — why: evita imóvel meio salvo e agenciamento duplicado.

- NFS-e: perfil fiscal não exige aprovação nem autorização de produção; sem perfil cadastrado vale `defaultRentalFiscalProfile` (administração, tomador = proprietário, endereço = imóvel, valor = comissão mensal, competência = mês anterior) — why: o usuário definiu que aprovação contábil não bloqueia teste nem emissão real.
- Busca global e Integrações são ferramentas internas de Configurações e exclusivas do administrador; não aparecem como itens próprios na navegação principal — why: mantém a barra lateral simples e centraliza ferramentas administrativas.

- Galeria nos sites ImobiBrasil: a ordem exibida é capa + códigos de imagem em ordem crescente (`displayOrder`); envio sempre crescente, e reconstrução só "envia primeiro, apaga depois" (máx. 2 exclusões/rodada, disjuntor 80%, só com leitura confiável); reconstrução nova só por pedido do admin — why: apagar antes de repor esvaziou galerias e a ordem da lista da API não é a do site.

- Rental Emissões is a presentation layer: open the existing RentalNfseSection through an explicit UI request, never duplicate or alter NFS-e transmission rules — why: existing fiscal confirmations remain the single flow.
- Receipts use a pure model and client-side pdf-lib rendering; authenticated server functions register and sign private rental_emissions files under contract-scoped storage policies — why: document generation stays separate from fiscal services and ownership remains enforced.
- Boleto providers follow the browser-safe provider interface; no configured provider means no financial issuance — why: simulated payment documents must never be mistaken for payable boletos.
- Ad platform tokens (ad_platform_connections) are read only server-side via the admin client inside handlers; the browser sees connections through the `ad_connections_public()` RPC — why: OAuth tokens must never reach the client.
- Marketing ad connectors live in src/lib/ads (pure link parser + per-platform providers implementing AdProvider); missing secrets surface as `not_configured`, never fake values — why: keeps manual campaigns working without credentials.
- Agent integrations (MCP) live in src/lib/mcp (one tool per file, OAuth via Supabase, queries via the caller token so RLS applies; read tools and approved OAuth clients may prepare proposals; execution only after a click in a personal Gestão session) — why: assistants must never see more than the signed-in user or execute business writes from an external credential.
- Shared selections (src/lib/selecoes): browser draft holds only property ids per user; create/edit/close go through SECURITY DEFINER RPCs (shared_selection_save/close) and the public page reads only shared_selection_public(token), whose closed field list and shared_selection_property_eligible rule are the single public-eligibility source — why: atomic, idempotent writes and no private data on the anonymous link.
